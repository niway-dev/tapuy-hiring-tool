## Shared Decisions

| Decision                            | Why                                                                                     |
| ----------------------------------- | --------------------------------------------------------------------------------------- |
| Domain constants pattern for enums  | Type-safe values shared between domain, database, and UI layers                         |
| Zod schemas as source of truth      | Single definition drives validation, types, and API contracts                           |
| Eden Treaty for API type safety     | End-to-end type safety from Elysia backend to React frontend                            |
| Dashboard reads served by Drizzle   | One ORM owns the list; `infra-prisma-db` is frozen as a swap demo and gets no new work  |
| New capabilities in a separate port | Growing `IHiringProcessRepository` would force the frozen Prisma implementation to grow |

## Shared Gotchas

- Database enums must use domain constant values arrays (`SALARY_RATE_TYPE_VALUES`) to stay in sync.
- Form default values must match database defaults for backward compatibility when adding new fields.
- ⚠️ Schema changes ship via `bun run db:push` — there are no migration files. Code and database must land together, because Drizzle's `select()` names every schema column.
- ⚠️ `apps/web` has no `check-types` script, so nothing type-checks the frontend. Run `cd apps/web && bunx tsc --noEmit` by hand and ignore the `../server/` noise.
- ⚠️ Turbo caches `check-types`; when in doubt after touching a shared package, add `--force`.
